# Melhorias de campo RFD8500 — 26/10/2026

Implementado nesta branch:
- Beep e vibração Android para **leitura aceita**, acionados pela ponte nativa `ZebraNative.feedback()`.
- Bloqueio de releitura da mesma tag durante 5000 ms (tempo da última leitura aceita); outros chips não bloqueados.
- Registro mais recente primeiro na UI; TXT continua cronológico.
- Teclado numérico no coletor manual.
- Indicador textual/colorido dos eventos de conexão do SDK.
- Histórico preservado ao iniciar/encerrar sessão e persistido em `localStorage` da WebView. Erro de gravação é mostrado ao operador.
- Compartilhamento por Intent.ACTION_SEND nativo (WhatsApp e demais aplicativos instalados).

**Ressalvas operacionais:**
- `localStorage` não equivale a um banco transacional com fila durable; limpeza de dados/desinstalação pode apagar os registros. Exportar backups e migrar futuramente a SQLite com confirmação de gravação ANTES do feedback.
- A API online não foi ativada. O projeto anterior `ulissesmtb/rfidbox-sync` envia **chunks com offset** da RFIDBox para `https://corridaeaventura.com.br/crono/api/upload.php`, usando token obtido por pareamento com a **RFIDBox** via `/api/pair.php`. O RFD8500 envia leituras locais sem a RFIDBox. Reutilizar o endpoint sem autenticação/token/chunk compatível seria inseguro e poderia duplicar registros.
- O FTP do projeto original permanece **simulado**; nenhuma leitura é marcada como enviada.
- Para ativar a API é necessário estabelecer autenticação própria para o novo coletor, formato de lote incremental, confirmação/idempotência e armazenamento de fila com reenvio.
- O sinal sonoro e a vibração precisam de teste físico; `navigator.vibrate` não é usado.
- Compilação GitHub Actions e testes do hardware devem confirmar a nova versão antes de utilizar em evento.
